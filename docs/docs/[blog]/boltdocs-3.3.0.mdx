## We did it: Boltdocs 3.3.0 beats Docusaurus Faster

We set out to build the fastest documentation framework in the JavaScript ecosystem. Today, with **Boltdocs 3.3.0**, we are proud to announce that Boltdocs officially outperforms **Docusaurus Faster** in both Cold Build speed and Dev Server Startup time.

<Callout type="info">
  In comparative benchmarks on a 100-page site:
  - **Cold Build Speed**: **11.41s** vs Docusaurus **15.26s** (**3.85s / 34% faster**)
  - **Dev Server Startup**: **4.31s** vs Docusaurus **4.52s** (**210ms faster**)
  - **Incremental MDX HMR**: **0.36s** (**7x faster**)
</Callout>

## How We Won: Under the Hood

### 1. Early Async Sätteri MDX Precompilation
Instead of waiting for Vite's `buildStart()` hook to compile Markdown ASTs, Sätteri now starts Rust worker pool precompilation inside `configResolved()`. This allows worker threads to compile MDX files concurrently while Vite initializes its plugin graph.

### 2. Dynamic Piscina & Sätteri Pool Sizing
Rather than spawning 7 fixed workers on multi-core CPUs (which caused CPU thread contention and IPC overhead), worker counts now scale dynamically (`Math.min(cpus, Math.ceil(files/25))`), using 4 optimal workers for 100 pages.

### 3. Non-Blocking Dev Startup & Lazy Route Generation
`generateRoutes()` no longer blocks `server.listen()`. The dev server starts listening immediately and computes route trees in the background before the browser issues its first HTTP request.

## 🎨 CSS-Framework Agnostic Core & Official Plugins

Before 3.3.0, core had hardcoded Tailwind CSS checks. In 3.3.0, **Boltdocs is 100% CSS-Framework Agnostic**:

1. **Vanilla CSS Native Core**: Core natively supports `.css` files, CSS Modules, and custom properties out of the box with zero external dependencies. `base-theme.css` provides built-in design tokens for `ui-base` components.
2. **Expanded Plugin API**: Plugins can now register custom PostCSS plugins, preprocessor options, and CSS files via `css: { postcssPlugins, preprocessorOptions }`.
3. **New Official Styling Plugins**:
   - 🎨 **`@bdocs/plugin-tailwindcss`**: Full Tailwind CSS v4 support via `@tailwindcss/vite`.
   - ⚡ **`@bdocs/plugin-sass`**: SASS / SCSS preprocessor support.
   - 🚀 **`@bdocs/plugin-unocss`**: Atomic UnoCSS engine support.

## 🔌 Next-Gen Decoupled Plugin API (`definePlugin`)

Boltdocs 3.3.0 introduces the **Next-Generation Plugin API**, inspired by Astro's clean integration model. The new API makes creating plugins incredibly intuitive and paves the way for modularizing all core features (Search, Analytics, Feedback, SEO/Sitemaps, UI Primitives) into standalone packages.

### Key Highlights of the New Plugin API:

- 🛠️ **`definePlugin`**: A fluent, type-safe helper with complete TypeScript inference for options and lifecycle hooks.
- 🎨 **Client UI Slots (`client.slots`)**: Plugins can inject React components into dynamic slots (`'header:right'`, `'search:dialog'`, `'page:after'`, `'footer:bottom'`) without tight coupling to layout packages.
- ⚛️ **App Providers (`client.providers`)**: Plugins can wrap the root React tree with context providers (`SearchProvider`, `AnalyticsProvider`).
- 📝 **Frontmatter Transformation (`frontmatter:transform`)**: Intercept and compute custom metadata (`readingTime`, `lastUpdated`, custom author tags) before MDX compilation.
- 🔎 **Agnostic Search Contract (`search:index`)**: Core passes a standard `SearchDocument[]` array to search plugins, decoupling the core from specific search engines.
- 📦 **Post-SSG Asset Generation (`build:generate`)**: Post-build hook for sitemaps, RSS feeds, robots.txt, and OG images.

```ts
import { definePlugin } from 'boltdocs'

export default definePlugin<MyOptions>((options) => ({
  name: 'my-custom-plugin',
  client: {
    slots: {
      'header:right': './components/HeaderActions.tsx',
      'search:dialog': './components/SearchModal.tsx',
    },
    providers: ['./providers/SearchProvider.tsx'],
  },
  hooks: {
    'frontmatter:transform'(ctx, { frontmatter, rawContent }) {
      return {
        ...frontmatter,
        readingTime: Math.ceil(rawContent.split(/\s+/).length / 200),
      }
    },
    'search:index'(ctx, { documents }) {
      ctx.logger.info(`Indexed ${documents.length} search documents.`)
    },
    'build:generate'(ctx, { routes, outDir }) {
      ctx.logger.info(`Generated assets for ${routes.length} routes in ${outDir}.`)
    },
  },
}))
```

## Upgrading to 3.3.0

Upgrade all packages in your monorepo or project:

```bash
pnpm add boltdocs@latest @bdocs/ssg@latest
```

If you use Tailwind CSS v4, simply add `@bdocs/plugin-tailwindcss`:

```ts
// boltdocs.config.ts
import { defineConfig } from 'boltdocs'
import tailwindcssPlugin from '@bdocs/plugin-tailwindcss'

export default defineConfig({
  plugins: [
    tailwindcssPlugin(),
  ],
})
```
