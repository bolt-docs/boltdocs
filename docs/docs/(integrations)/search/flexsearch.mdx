## The `useSearch()` Hook

To build a custom search bar, query inputs, or inline list search, use the `useSearch()` hook from `boltdocs`. It exposes live query state, search results, and dialog control callbacks.

```tsx
import { useSearch } from 'boltdocs'

export function MySearchBar() {
  const { query, setQuery, results, isOpen, open, close } = useSearch()

  return (
    <div className="search-container">
      <input
        value={query}
        onChange={(e) => setQuery(e.target.value)}
        placeholder="Type to search..."
        onFocus={open}
      />
      {isOpen && results.length > 0 && (
        <div className="search-dropdown">
          {results.map((result) => (
            <a key={result.path} href={result.path} className="search-item">
              <span className="search-title">{result.title}</span>
              <p className="search-desc">{result.description}</p>
            </a>
          ))}
        </div>
      )}
    </div>
  )
}
```


### `SearchResult`

| Property | Type | Description |
| :--- | :--- | :--- |
| **`path`** | `string` | The resolved absolute path (e.g. `'/docs/guides/getting-started'`). |
| **`title`** | `string` | The matching page title. |
| **`description`** | `string` | The page description (from frontmatter or excerpt). |
| **`headings`** | `HeadingMatch[]` | Sub-headings (`h2`–`h6`) within the page that matched the search query. |

## Local Development vs. Production

* **Local Development:** The search index updates incrementally via Vite HMR as you edit files, making live search change testing seamless.
* **Production:** The index is bundled into a separate chunk-split package that loads asynchronously only when the user interacts with the search input, keeping the initial bundle load size extremely minimal.
