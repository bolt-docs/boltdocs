# `ctx.hmr` — PluginHmrAPI

Conéctate al pipeline de file-watching del dev server y envía eventos
personalizados a los clientes conectados.

```ts
ctx.hmr.onFileChange(async (filePath) => {
  ctx.logger.info(`Archivo modificado: ${filePath}`)
})
ctx.hmr.onFileAdd((filePath) => {
  ctx.logger.info(`Nuevo documento: ${filePath}`)
})
ctx.hmr.send('mi-plugin:update', { reason: 'regenerado' })
```

---

## Tipos de eventos

| Método | Tipo de evento | Cuándo se dispara |
| :--- | :--- | :--- |
| `onFileAdd` | `'add'` | Nuevo archivo creado dentro de `docs/` |
| `onFileChange` | `'change'` | Archivo existente modificado |
| `onFileUnlink` | `'unlink'` | Archivo eliminado de `docs/` |
| `onFileEvent(type, fn)` | any | Bajo nivel — escucha un tipo de evento específico |

Todos los handlers reciben la **ruta absoluta normalizada** y se
ejecutan después del procesamiento HMR del core. Los errores en los
handlers de plugins son capturados y registrados — nunca detienen el
dev server.
