El objeto `PluginContext` que recibe cada hook del lifecycle incluye
siete namespaces enriquecidos que otorgan a los plugins acceso seguro
y tipado a la maquinaria interna del core: **caches**, **diagnostics**,
**paths**, **virtual modules**, **middleware**, **server**
y **hmr**.

Esta sección es la referencia oficial de la API. Léela junto con la
[descripción general del Sistema de Plugins](/docs/es/plugins/) para
conocer la arquitectura y ejemplos.

Cada namespace tiene su propia página — usa el sidebar o las tarjetas
a continuación para navegar.

## Ejemplo completo

Un plugin real que cachea una transformación costosa, reporta progreso,
resuelve una ruta y registra un módulo virtual:

```ts
import { definePlugin } from 'boltdocs'

export default definePlugin<MisOpciones>((options) => ({
  name: 'mi-plugin-inteligente',
  client: {
    slots: {
      'header:right': './components/HeaderActions.tsx',
      'search:dialog': './components/SearchModal.tsx',
    },
    providers: ['./providers/SearchProvider.tsx'],
    mdxComponents: { Callout: './components/Callout.tsx' },
  },
  hooks: {
    'frontmatter:transform'(ctx, { frontmatter, rawContent }) {
      return {
        ...frontmatter,
        readingTime: Math.ceil(rawContent.split(/\s+/).length / 200),
      }
    },
    'search:index'(ctx, { documents }) {
      ctx.logger.info(`Indexados ${documents.length} documentos de búsqueda.`)
    },
    'build:generate'(ctx, { routes, outDir }) {
      ctx.logger.info(`Assets generados para ${routes.length} rutas en ${outDir}.`)
    },
  },
}))
```
