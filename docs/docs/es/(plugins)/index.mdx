## Inicio Rápido

Un plugin de Boltdocs es un objeto JavaScript simple. Puedes escribir un plugin directamente en tu archivo de configuración o distribuirlo como un paquete npm.

Aquí hay un plugin mínimo que registra un mensaje cuando comienza la compilación de la documentación:

```ts title="boltdocs.config.ts"
import { defineConfig, type BoltdocsPlugin } from 'boltdocs'

export function myCustomPlugin(): BoltdocsPlugin {
  return {
    name: 'boltdocs-plugin-hello',
    hooks: {
      beforeBuild(ctx) {
        ctx.logger.info(`Hello! Docs are configured at URL: ${ctx.config.siteUrl}`)
      },
    },
  }
}

export default defineConfig({
  plugins: [myCustomPlugin()],
})
```

## Conceptos y Arquitectura

Boltdocs equilibra la extensibilidad completa con la máxima seguridad. Para garantizar que el entorno de desarrollo mantenga una velocidad excepcional, omitimos los contenedores de sandbox complejos y los permisos dinámicos. Los plugins se ejecutan de forma nativa, pero sus acciones están protegidas por nuestra capa de seguridad estática.

### 🛡️ El Parche Quirúrgico del Sistema de Archivos

Boltdocs aplica automáticamente monkey-patches a los módulos nativos de Node `fs` y `fs/promises` durante la ejecución. Esta protección defiende tu estación de trabajo contra errores accidentales o scripts no deseados al imponer restricciones estrictas de escritura/eliminación:

* **Límites del Workspace:** Los plugins solo pueden escribir o eliminar archivos dentro del directorio raíz del proyecto.
* **Acceso Sensible:** Las operaciones sobre archivos `.env` se bloquean inmediatamente.
* **Integridad del Registro:** La escritura en `node_modules` está deshabilitada, excepto para cachés de compilación locales designadas como `node_modules/.vite`.

Si un plugin realiza una escritura o eliminación que viola estos límites, se lanza una excepción de seguridad y el proceso de compilación/desarrollo se detiene instantáneamente.

### ⚠️ Advertencias de Scripts de Instalación

Cada vez que inicias el framework mediante `boltdocs dev` o `boltdocs build`, Boltdocs inspecciona las configuraciones de `package.json` de todos los plugins instalados. Si algún paquete declara scripts de ciclo de vida `install`, `preinstall` o `postinstall`, la consola muestra una advertencia. Esto te ayuda a detectar triggers de scripts ocultos antes de que se ejecuten en tu máquina.

### 🔍 Auditoría de Código Estático

Antes de desplegar cambios o compilar los assets estáticos finales, puedes auditar las dependencias de tus plugins directamente:

```bash
boltdocs audit
```

Este escáner realiza un análisis estático rápido del código fuente de todos los plugins activos. Verifica:
* **Operaciones de Red:** Llamadas a `fetch(`, `axios`, `http.request` o `https.request`.
* **Extracción de Entorno:** Accesos a claves de `process.env`.

El comando genera un reporte tabular que indica si los plugins están completamente limpios o requieren auditorías de advertencia.

## Referencia de la API

### BoltdocsPlugin

Define la estructura y los campos de integración para una extensión de Boltdocs.

| Propiedad | Tipo | Predeterminado | Descripción |
| :--- | :--- | :--- | :--- |
| **`name`** | `string` | `(Requerido)` | Un identificador único para el plugin (por ejemplo, `'boltdocs-plugin-mermaid'`). |
| **`enforce`** | `'pre' \| 'post'` | `'post'` | Controla el orden de ejecución relativo a los plugins del sistema central. |
| **`version`** | `string` | `undefined` | La cadena de versión semántica del plugin. |
| **`boltdocsVersion`** | `string` | `undefined` | Un rango semver que indica las versiones compatibles del framework Boltdocs. |
| **`remarkPlugins`** | `unknown[]` | `[]` | Plugins de Remark inyectados en el pipeline de compilación MDX. |
| **`rehypePlugins`** | `unknown[]` | `[]` | Plugins de Rehype inyectados en el pipeline de compilación MDX. |
| **`vitePlugins`** | `VitePlugin[]` | `[]` | Plugins de Vite personalizados añadidos a la instancia interna del compilador. |
| **`components`** | `Record<string, string>` | `{}` | Registra nombres de componentes JSX globales vinculados a módulos del cliente. |
| **`hooks`** | [`PluginLifecycleHooks`](#pluginlifecyclehooks) | `undefined` | Callbacks de hooks ejecutados en puntos específicos del ciclo de vida del framework. |

### PluginLifecycleHooks

Firmas de callback para conectarse a los ciclos de vida de compilación y servidor.

| Propiedad | Tipo | Predeterminado | Descripción |
| :--- | :--- | :--- | :--- |
| **`beforeBuild`** | `(ctx: PluginContext) => void \| Promise<void>` | `undefined` | Se ejecuta justo antes de que comience la compilación del sitio estático. |
| **`afterBuild`** | `(ctx: PluginContext) => void \| Promise<void>` | `undefined` | Se ejecuta inmediatamente después de que una compilación de producción tenga éxito. |
| **`beforeDev`** | `(ctx: PluginContext) => void \| Promise<void>` | `undefined` | Se ejecuta antes de que el servidor de desarrollo local comience a escuchar. |
| **`afterDev`** | `(ctx: PluginContext) => void \| Promise<void>` | `undefined` | Se ejecuta cuando el servidor de desarrollo está completamente inicializado y activo. |
| **`buildEnd`** | `(ctx: PluginContext) => void \| Promise<void>` | `undefined` | Se ejecuta al completar el proceso, ya sea con éxito o error. |
| **`transformSource`** | `(ctx: PluginContext, params: { code: string; filePath: string }) => Promise<{ code: string }> \| { code: string }` | `undefined` | [Nuevo] Se ejecuta sobre el código fuente MDX sin compilar antes de la compilación. Transforma delimitadores de matemáticas `$`/`$$` u otros patrones de texto antes de que el parser MDX los procese. Utiliza un patrón de cadena. |
| **`transformMdx`** | `(ctx: PluginContext, params: { code: string; filePath: string }) => Promise<{ code: string }> \| { code: string }` | `undefined` | Se ejecuta sobre el código JavaScript MDX compilado para inyectar o modificar código de ejecución. Utiliza un patrón de cadena. |
| **`transformHtml`** | `(ctx: PluginContext, params: { html: string; path: string }) => Promise<{ html: string }> \| { html: string }` | `undefined` | Se ejecuta durante la generación SSG para transformar páginas HTML compiladas. Utiliza un patrón de cadena. |

### PluginContext

Contexto de entorno con namespace proporcionado a todos los hooks de ciclo de vida.

| Propiedad | Tipo | Predeterminado | Descripción |
| :--- | :--- | :--- | :--- |
| **`config`** | `Readonly<BoltdocsConfig>` | `Definido por el sistema` | Acceso de solo lectura a la estructura de configuración del sitio resuelta. |
| **`logger`** | `PluginLogger` | `Definido por el sistema` | Wrapper de logging que soporta salidas `info`, `warn`, `error` y `debug`. |
| **`store`** | `PluginStore` | `Definido por el sistema` | Almacenamiento de estado con namespace para intercambiar valores entre plugins. |
| **`meta`** | `PluginMeta` | `Definido por el sistema` | Metadatos de identidad resueltos del plugin en ejecución. |

## Ejemplos Prácticos

### Transformaciones MDX Personalizadas

Conecta plugins de Remark para extender el procesamiento de Markdown (por ejemplo, parseando Github Flavored Markdown):

```ts
import remarkGfm from 'remark-gfm'
import type { BoltdocsPlugin } from 'boltdocs'

export function gfmPlugin(): BoltdocsPlugin {
  return {
    name: 'boltdocs-plugin-gfm',
    remarkPlugins: [remarkGfm],
  }
}
```

### Registro de Componentes Globales

Expón componentes React globalmente para que puedan escribirse dentro de cualquier archivo `.md` o `.mdx` sin importaciones:

```ts
import type { BoltdocsPlugin } from 'boltdocs'

export function chartsPlugin(): BoltdocsPlugin {
  return {
    name: 'boltdocs-plugin-charts',
    components: {
      BarChart: '@bdocs/plugin-charts/client',
      LineChart: '@bdocs/plugin-charts/client',
    },
  }
}
```

### Comunicación entre Plugins

Utiliza la interfaz compartida `store` para coordinar configuraciones entre plugins independientes:

```ts
import type { BoltdocsPlugin } from 'boltdocs'

// Plugin A establece variables de estado
export const pluginA = (): BoltdocsPlugin => ({
  name: 'plugin-a',
  hooks: {
    beforeBuild(ctx) {
      ctx.store.set('plugin-a', 'custom-key', { resolved: true })
    },
  },
})

// Plugin B lee el estado establecido
export const pluginB = (): BoltdocsPlugin => ({
  name: 'plugin-b',
  hooks: {
    beforeBuild(ctx) {
      const data = ctx.store.get('plugin-a', 'custom-key')
      ctx.logger.info(`Retrieved data from Plugin A: ${JSON.stringify(data)}`)
    },
  },
})
```

<Callout variant="tip" title="Mantenlo Limpio">
  Se recomienda que los plugins escriban salidas temporales o cachés de compilación dentro del directorio designado `.boltdocs/` del workspace, el cual es completamente accesible y está ignorado por el control de versiones.
</Callout>
