La primitiva `Popover` es un contenedor superponible utilizado para renderizar menús, tooltips, formularios de selección o widgets de ventana emergente contextuales personalizados activados por botones de anclaje.

## Inicio Rápido

Una implementación básica de Popover dentro de un `MenuTrigger`. El disparador es un `Button`:

```tsx
import { Button, Menu, MenuItem, MenuTrigger, Popover } from '@bdocs/primitives'

export default function ConfigPopover() {
  return (
    <MenuTrigger className="absolute top-full left-0 mt-2 z-50">
      <Button className="px-4 py-2 bg-primary-500 text-white rounded-lg">
        Configuración
      </Button>
      <Popover className="p-4 bg-surface border border-subtle rounded-xl shadow-xl max-w-sm">
        <h4 className="font-bold mb-2">Configuración del Espacio de Trabajo</h4>
        <p className="text-xs text-muted mb-4">Ajusta las banderas del compilador y objetivos del proyecto a continuación.</p>
        <Menu aria-label="Banderas del compilador">
          <MenuItem data-key="strict">Modo estricto</MenuItem>
          <MenuItem data-key="fast">Transpile rápido</MenuItem>
        </Menu>
      </Popover>
    </MenuTrigger>
  )
}
```

---

## Props del Componente

| Propiedad | Tipo | Predeterminado | Descripción |
| :--- | :--- | :--- | :--- |
| **`children`** | `ReactNode` | *Requerido* | Elementos hijos a renderizar dentro del marco de contenido de la superposición del popover. |
| **`className`** | `string` | `undefined` | Sobrescrituras de clases CSS utilitarias personalizadas. |
| **`style`** | `CSSProperties` | `undefined` | Sobrescrituras de estilo en línea. |

---

## Posicionamiento

`Popover` se posiciona con CSS respecto a su disparador y no lleva ninguna prop
`placement`, `offset` ni `crossOffset`. De ahí se siguen dos consecuencias, ambas
deliberadas:

- **Lo colocas con `className`.** El contenedor del disparador es
  `position: relative`, así que `absolute top-full left-0 mt-2` deja el popover
  debajo de su disparador. Por eso `MenuTrigger` recibe un `className` para el
  popover en lugar de un `placement`.
- **No voltea ni esquiva el borde de la ventana.** No hay solucionador de
  colisiones. Boltdocs ancla los popovers a elementos de la navbar y de la barra
  lateral, donde el diseño circundante ya decide qué lado está libre, así que un
  popover cerca del borde de una ventana estrecha se desbordará en lugar de
  reposicionarse.

---

## Personalización y estados

`Popover` es un overlay flotante sin visuales propios — colores, bordes, radios y sombras vienen del tema mediante `className`, que es un passthrough de cadena simple (esta primitiva no desempaqueta la forma de función de renderizado). Las transiciones de entrada y salida se controlan enteramente por clases CSS en el contenedor del disparador, porque no hay ningún ciclo de vida de posicionamiento que necesite notificarlo.

| Estado / Slot | Mecanismo |
| :--- | :--- |
| `className` | Passthrough de cadena simple fusionado en el overlay; el tema controla colores, bordes, radios, sombras |
| `hidden` | Presente en el contenedor del popover mientras el disparador está cerrado, de modo que un popover cerrado no ocupa espacio y es omitido por la tecnología asistiva |

Tailwind v4:

```tsx
<Popover className="animate-in fade-in zoom-in-95 rounded-xl bg-surface border border-subtle shadow-xl p-4">
  <div>Contenido del popover</div>
</Popover>
```
