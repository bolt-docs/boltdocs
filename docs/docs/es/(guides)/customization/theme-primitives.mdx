Toda primitiva en Boltdocs es **neutra de estilo**. El comportamiento vive en `@bdocs/primitives` y `@bdocs/runtime`; el aspecto por defecto vive en `@bdocs/theme-neutral`. Tu tema posee todas las decisiones visuales. Esto permite que dos sitios completamente distintos corran sobre el mismo código de componentes.

```text
primitiva  →  <aside data-sidebar-root> + data-active, data-open, data-depth …
               estructura + comportamiento + estado (sin colores, sin tamaños)

tema       →  CSS nativo dirigido a esos atributos data-*
               colores, bordes, espaciado, transiciones — todo tuyo
```

## El Contrato

Una primitiva renderiza HTML semántico, conecta el comportamiento (abrir/cerrar, navegación con teclado, detección de ruta activa, seguimiento de scroll) y expone su **estado a través de atributos `data-*` que están presentes solo cuando son verdaderos**. Tu tema nunca necesita saber *cómo* se calcula el estado, solo *que* existe.

```tsx
// Lo que renderiza el framework cuando un enlace del sidebar está activo:
<a href="/docs/guides" data-active aria-current="page" …>
  Guides
</a>
```

```css
/* Lo que hace tu tema con eso: */
a[data-active] {
  color: var(--bdocs-primary);
  background: var(--bdocs-primary-soft-10);
}
```

El tema por defecto entrega **CSS nativo** en `src/styles/`. No necesitas Tailwind y ninguno de los paquetes del core asume un framework CSS.

## ¿Qué Estado Expone Cada Primitiva?

| Primitiva | Atributos de estado | Comportamiento |
| :--- | :--- | :--- |
| **`Disclosure`** (grupos del sidebar) | `data-open`, `data-collapsible`, `aria-expanded`, `aria-controls` | Expandir/cerrar, auto-apertura del grupo activo |
| **`Navbar`** | `data-open`, `aria-expanded`, `aria-controls` | Drawer móvil, dropdown por hover, clic fuera, Escape |
| **`Tabs`** | `data-selected`, `aria-selected`, `aria-controls` | Roving tabindex, flechas y Home/End |
| **`Group`** | `data-orientation`, `data-disabled` | Semántica accesible de agrupación |
| **Scroll spy** (`OnThisPage`) | `data-active`, `data-level`, `data-otp-*` | IntersectionObserver, geometría del indicador, auto-scroll |

## Dónde Viven los Valores por Defecto

El aspecto que obtienes de forma predeterminada está implementado en `@bdocs/ui-base`:

- `src/composition/` — wrappers delgados sobre `@bdocs/primitives`.
- `src/ui-base/` — la UI ensamblada (navbar, sidebar, diálogo de búsqueda, …).
- `src/styles/components/` — un archivo CSS nativo por componente.

`@bdocs/theme-neutral` ensambla esas piezas en el layout de documentación por defecto y posee los componentes MDX; re-exporta la API de UI por retrocompatibilidad.

Cada wrapper acepta slots de `className` (además de `itemClassName`, `linkClassName`, `indicatorClassName` y `fadeClassName` cuando el slot se repite por elemento). Esas clases se combinan con los valores por defecto y pueden reemplazarse por completo.

```tsx
// docs/src/theme/on-this-page.tsx
import { OnThisPage as Primitive } from '@bdocs/ui-base/composition'

export function OnThisPage() {
  return (
    <Primitive.Root className="my-toc">
      <Primitive.Header className="my-toc__header">On this page</Primitive.Header>
      <Primitive.Tree
        headings={currentRoute.headings}
        className="my-toc__list"
        itemClassName="my-toc__item"
        linkClassName="my-toc__link"
        indicatorClassName="my-toc__indicator"
      />
    </Primitive.Root>
  )
}
```

```css
.my-toc__link { display: block; padding-block: 0.125rem; }
.my-toc__link[data-active] { color: var(--bdocs-primary); }
```

Los nombres de clase son tuyos; los atributos `data-*` que apuntan son el contrato estable y documentado.

## Dar Estilo Sin un Paquete de Tema

Puedes omitir `@bdocs/theme-neutral` y renderizar las primitivas directamente. Entrega tu propio objeto `surface` al engine y usa `@bdocs/primitives` para el comportamiento que necesites: `Button`, `Menu`, `Tabs`, `Disclosure`, `Popover`, `Tooltip`, `Breadcrumbs`, `Group`, `ScrollSpyProvider` y el resto. No hay nombres de clase generados por un framework que debas reversear.
