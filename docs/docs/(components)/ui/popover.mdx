The `Popover` primitive is an overlay container used to render menus, tooltips, selection forms, or custom contextual popup widgets triggered by anchor buttons.

## Quick Start

A basic Popover inside a `MenuTrigger`. The trigger is a `Button`:

```tsx
import { Button, Menu, MenuItem, MenuTrigger, Popover } from '@bdocs/primitives'

export default function ConfigPopover() {
  return (
    <MenuTrigger className="absolute top-full left-0 mt-2 z-50">
      <Button className="px-4 py-2 bg-primary-500 text-white rounded-lg">
        Settings
      </Button>
      <Popover className="p-4 bg-surface border border-subtle rounded-xl shadow-xl max-w-sm">
        <h4 className="font-bold mb-2">Workspace Settings</h4>
        <p className="text-xs text-muted mb-4">Adjust the compiler flags and project targets below.</p>
        <Menu aria-label="Compiler flags">
          <MenuItem data-key="strict">Strict mode</MenuItem>
          <MenuItem data-key="fast">Fast transpile</MenuItem>
        </Menu>
      </Popover>
    </MenuTrigger>
  )
}
```

---

## Component Props

| Property | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| **`children`** | `ReactNode` | *Required* | Child elements to render inside the popover overlay content frame. |
| **`className`** | `string` | `undefined` | Custom utility CSS class overrides. |
| **`style`** | `CSSProperties` | `undefined` | Inline style overrides. |

---

## Positioning

`Popover` is positioned with CSS relative to its trigger, and carries no
`placement`, `offset` or `crossOffset` prop. Two consequences follow from that,
and both are deliberate:

- **You place it with `className`.** The trigger wrapper is
  `position: relative`, so `absolute top-full left-0 mt-2` puts the popover
  below its trigger. This is why `MenuTrigger` takes a `className` for the
  popover rather than a `placement`.
- **It does not flip or avoid the viewport edge.** There is no collision solver.
  Boltdocs anchors popovers to navbar and sidebar items where the surrounding
  layout already decides which side is free, so a popover near the edge of a
  narrow window will overflow rather than reposition itself.

---

## Customization & states

`Popover` is a floating overlay with no visuals of its own — colors, borders, radius, and shadows all come from the theme through `className`, which is a plain string passthrough (this primitive does not unwrap the render-function form). Enter and exit transitions are driven entirely by CSS classes on the trigger wrapper, because there is no positioning lifecycle that needs to report one.

| State / Slot | Mechanism |
| :--- | :--- |
| `className` | Plain string passthrough merged onto the overlay; theme controls colors, borders, radius, shadow |
| `hidden` | Present on the popup container while the trigger is closed, so a closed popover takes no space and is skipped by assistive technology |

Tailwind v4:

```tsx
<Popover className="animate-in fade-in zoom-in-95 rounded-xl bg-surface border border-subtle shadow-xl p-4">
  <div>Popover content</div>
</Popover>
```
